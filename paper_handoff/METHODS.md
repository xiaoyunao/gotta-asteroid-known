# Methods

## End-To-End Workflow

The processing chain converts per-exposure photometric catalogs into a known-asteroid matched detection table:

1. Scan catalog files for a night or date range.
2. Read each FITS catalog header and source table.
3. Build WCS from the header and determine the exposure midpoint.
4. Estimate the image footprint from the WCS-transformed CCD corners.
5. Query known-asteroid ephemerides for the field and epoch.
6. Reject ephemeris candidates that do not fall inside the CCD footprint.
7. Match predicted asteroid RA/Dec to detected catalog source positions.
8. Merge the matched asteroid ephemeris row and source-catalog row.
9. Merge per-file or per-night results into a cumulative history table.
10. Add SBDB object/orbit metadata and JPL Horizons geometry/rate quantities.
11. Generate statistics and figures from the filtered GOTTA-only table.

## Field Geometry

For each exposure, the script reads `NAXIS1`, `NAXIS2`, and WCS keywords from the catalog header. It maps the four CCD corners from pixel coordinates to sky coordinates and uses the image center as the field center. The search radius is the maximum angular distance from the center to a corner plus a small padding.

The documented defaults are:

- `corner_pad = 0.05 deg`
- `confidence_pad = 0.5 deg`

These pads reduce edge losses from WCS and query-boundary effects.

## Observation Epoch

The matching uses the exposure midpoint:

```text
epoch = DATE-OBS + EXPTIME / 2
```

The output table stores `epoch` as MJD. The code reads common time-key variants such as `OBS_DATE`, `DATE-OBS`, and `DATEOBS`.

## Known-Object Ephemeris Query

The matching script uses `aleph.Query` with the Lowell `astorb.dat` catalog. The observer location is Xinglong:

| Quantity | Value |
|---|---:|
| Longitude | 117.575 deg |
| Latitude | 40.393 deg |
| Height | 960 m |

The current engineered script documents a default predicted magnitude limit of `22.5`; an earlier remote GOTTA script used `23`.

## CCD Footprint Filter

The initial circular field query can return objects outside the rectangular CCD. The script transforms predicted asteroid RA/Dec back into pixel coordinates and keeps only objects satisfying:

```text
1 <= x_pix <= nx
1 <= y_pix <= ny
```

## Astrometric Matching

Predicted asteroid coordinates and catalog source coordinates are represented as `SkyCoord` objects. The code uses nearest-neighbor sky matching between predicted positions and catalog positions. The engineered SMT-derived script documents a default angular match threshold of `1 arcsec`; the earlier remote script used `3 arcsec`.

The script also supports a predicted-minus-measured magnitude consistency filter:

```text
abs(predicted_mag - Mag_Kron) < magdiff
```

The exact value used to produce `gotta_asteroids.fits` was not found in the repository.

## SBDB And JPL Enrichment

After matching, SBDB enrichment adds object identity and orbit information, including orbit class and orbital elements. JPL Horizons enrichment adds heliocentric distance, topocentric distance, phase angle, RA/Dec rates, total angular rate, and a failure flag.

## Statistical Analysis

The final summary statistics are generated from `gotta_asteroids.fits` by `summarize_gotta_asteroids.py`. The script reports counts, orbit-class counts, selected magnitude and geometry distributions, and per-object detection counts.

## Plotting

The final plots are generated by `plot_gotta_asteroids.py`:

- `asteroid_orbits.png`: orbit class in semimajor-axis/eccentricity and semimajor-axis/inclination space.
- `gotta_radec_healpix_nside64.png`: HEALPix nside 64 sky distribution in a Mollweide RA/Dec projection.

The RA/Dec figure clips the color scale at 100 counts per HEALPix pixel for readability.
